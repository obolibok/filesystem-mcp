## R1–R8

- **R1:** tool до регистрации отклоняет lexical scratch selectors, а guarded open
  повторяет запрет для requested/resolved paths. Проверены metadata и готовый ZIP,
  canonical spelling, настоящий 8.3 alias и junction alias; новых доступных частей
  при отказе нет, source не меняется.
- **R2:** bundle использует явно принадлежащие producer lazy input streams. Ошибки
  input перенаправляются в ZIP output/job lifecycle. Удаление synthetic spool перед
  compression даёт `failed`, 0 artifacts и cleanup; тот же manager затем успешно
  выполняет следующую job, процесс не завершается.
- **R3:** при closed-ZIP split/oversized/cancel/error producer уничтожает и через
  `finished()` дожидается всех input/output streams. Две последовательные split/
  oversized jobs оставляют все наблюдаемые streams `destroyed` и не оставляют
  `.partial` files.
- **R4:** recoverable source classification ограничена guarded source open/read/
  restat. Synthetic `EACCES` перед scratch write теперь даёт fatal `failed`, а не
  per-file `inaccessible`; reservation освобождается, partial/artifacts отсутствуют,
  следующая job проходит.
- **R5:** manager принимает transient `reuseGuard` и перед выдачей prior status
  применяет ту же авторизацию root + selected paths, что status/fetch. Обычное
  удаление source сохраняет reuse immutable job; narrowing отклоняет reuse и до,
  и после restart. Guard не сохраняется в stored schema.
- **R6:** effective raw source limit — минимум `FS_BUNDLE_MAX_FILE_BYTES`,
  `FS_BUNDLE_MAX_RAW_PART_BYTES` и `FS_MAX_FILE_SIZE`. Отдельный regression
  отклоняет original выше general cap и разрешает хорошо сжимаемый original выше
  delivery cap, когда он ниже general source cap.
- **R7:** `PathGuard` lstat-проверяет каждый существующий компонент от canonical
  source root до leaf. Junction в другой allowed root с отсутствующим leaf fatal;
  обычный missing остаётся per-file outcome. Перед open проверяется regular file,
  поэтому POSIX FIFO не блокирует worker.
- **R8:** local harness до `mkdir` canonicalizes существующий output либо ближайший
  существующий ancestor. Canonical child, junction alias и Windows 8.3 alias в source
  отклоняются без изменения source/output.

Дополнительно selector schema отклоняет Windows-invalid `<>"|?*` и device names с
superscript digits (`COM¹`/`LPT¹`). Independent verifier теперь сопоставляет каждый
`archiveEntry` с фактическими `partArtifactId`/`partName` и выполняет negative control
с подменённой частью. Live teardown говорит об отсутствии незавершённых jobs.

Во время повторного volume profile обнаружен и до фиксации evidence исправлен новый
regression lazy producer: повторное использование одного chunk buffer могло менять
bytes, ещё удерживаемые compressor. Producer теперь копирует только текущий bounded
64 KiB slice; быстрый test содержит original больше трёх chunks, а volume verifier
повторно проверил все 7 MiB побайтово.
