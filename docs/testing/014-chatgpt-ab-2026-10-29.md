# 014: live ChatGPT stable/tree A/B для обработки — 2026-10-29

## Объём и свидетельства

В чате ChatGPT проекта SWB RAG сравнили stable R2 artifacts из 014 и tree R2
из 015. В каждом наборе по 2 843 566 файловых записей; обе jobs имеют
complete=false из-за 470 недоступных объектов. Независимое локальное сравнение
в [отчёте 015](015-local-r2-2026-10-29.md) подтвердило точные пути, размеры и
LastWriteTime каждого выданного файла.

В чате материализовали все 21 ZIP-part; SHA-256 совпал с manifests. В
восстановленном отчёте указаны размеры:

| Метрика | Stable | Tree |
| --- | ---: | ---: |
| Raw CSV | 473 957 770 B | 162 372 414 B |
| ZIP | 35 742 108 B | 25 664 531 B |
| Части | 11 | 10 |

Tree меньше на 65,7% по raw CSV и на 28,2% по ZIP.

## Обработка внутри чата

Для обоих форматов одним потоковым проходом выполнены три одинаковых вида
поиска; построение полного индекса path → (Length, LastWriteTime) повторено
трижды:

| Работа | Stable | Tree | Разница Tree |
| --- | ---: | ---: | ---: |
| Потоковый поиск | 5,1721 с | 4,1409 с | быстрее на 19,9% |
| Полный индекс, медиана трёх прогонов | 8,8542 с | 6,6547 с | быстрее на 24,8% |

Число результатов было одинаковым: точный путь — 1, basename-prefix — 4 679,
extension — 5 623. В локальном benchmark из отчёта 015 использовался другой
extension query и получено 5 738 совпадений; внутри каждого отдельного прогона
форматы дали одинаковые результаты.

Первоначальный ответ ChatGPT с отчётом показал “This response couldn’t load”.
Следующее сообщение восстановило эти значения из контекста предыдущего хода:
инструменты повторно не вызывались, части заново не скачивались, расчёты не
повторялись. Поэтому это восстановленный результат, а не новое независимое
исполнение. Чат оставался доступен и не сообщил, что разговор завершён.

Полный ход в интерфейсе занял около 6 мин 59 с, включая оркестрацию tools и
материализацию artifacts. Это не время одного парсера. Среда исполнения ChatGPT
и локальный Python harness в отчёте 015 также отличаются.

## Поведение materialization

Сначала материализовали реальный synthetic текстовый файл размером 7 bytes,
затем выбрали разрешение FileMCP на весь разговор. На этапе получения manifest
запрос разрешения повторился. После повторного выбора разрешения на весь разговор
все 21 части пришли без новых запросов. Повтор permission prompt и UI-ошибка
остаются отдельной проблемой ChatGPT; они не являются измерениями скорости парсера.

## Вывод и ограничения

Для проверенного R2 tree-depth-v1 уменьшил объём передачи и ускорил оба
измеренных consumer workload внутри чата. Локальная независимая проверка из
отчёта 015 подтверждает равенство выданных путей и метаданных. Это не доказывает
ускорение файлового обхода на сервере, более быстрое semantic reasoning для
любого запроса или одинаковую сквозную задержку на всех клиентах. Скилл модели
для этого прогона не понадобился: контракт дерева и manifest были доступны чату.
