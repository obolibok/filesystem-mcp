## Первый CI и причина исправления

Первый PR head: `9f39266454ebb5017523d2fd7940722fded51e0c`.
[CI run](https://github.com/obolibok/filesystem-mcp/actions/runs/35529481619):

- локальный полный `npm run check`: 380 tests, 373 pass, 0 fail, 7 прежних skips;
- Ubuntu CI: 380 tests, 377 pass, 0 fail, 3 platform skips;
- Windows CI: 143 pass, 56 fail, 181 cancelled. Основная ошибка startup:
  `FS_SNAPSHOT_DIR must not be a symlink or junction alias`.

Windows runner использует короткий 8.3 spelling системного TEMP. Менеджер сравнил
его с длинным realpath и ошибочно расценил различие как symlink/junction. Это
затрагивает настоящий startup с таким TEMP, поэтому смена TEMP только в CI не
является исправлением. Ошибка initialization затем отменяет зависимые tests.

## Проверка исправления перед merge

Менеджер проверяет scratch и всех ancestors через lstat до mkdir и повторно
после создания каталога. Реальные symlink/junction по-прежнему отклоняются;
Windows 8.3 spelling разрешён. После проверки canonical scratch используется
во всех служебных I/O, cleanup, source separation и исключении subtree из snapshot.

Пять новых регрессий выполнены без skips на Windows. До исправления: 2 PASS,
3 FAIL — оба short spelling не запускались, а отвергаемый ancestor junction
успевал создать каталог в target. После исправления: 5 PASS, 0 FAIL, 0 skips.
Проверены canonical, short-scratch и short-ancestor; реальный snapshot возвращает
только expected source file и исключает scratch. Leaf/ancestor junction отвергаются
до создания storage. Test type-check, ESLint и Prettier изменённых файлов — PASS.

Изменение runtime ограничено инициализацией и canonical scratch в job-manager;
CSV/ZIP producer, MCP contracts и delivery не менялись. Исходный
[живой опыт](003-live-2026-09-20.md) остаётся evidence этой передачи; новая startup
дельта проверена регрессиями. Перед merge повторяются полный локальный check и
Windows/Ubuntu CI; их окончательные результаты фиксирует центральная доска.
