## R3 — владение compression chain

Каждый bundle source теперь наблюдает синхронно создаваемую `yazl` pipe-chain и
передаёт producer во владение CRC/counter/`DeflateRaw`/counter streams. Перед
остановкой producer устанавливает ожидание `finished()` на output, sources и все
intermediate streams, затем явно уничтожает всю цепочку. Oversized, split, cancel,
source error и ZIP write error больше не оставляют native compressor до GC.

Regression восемь раз упаковывает плохо сжимаемый original 8 MiB при ZIP cap 64 KiB.
Тест намеренно удерживает сильные ссылки на все восемь `DeflateRaw`: после каждой
terminal job stream уже `destroyed=true` и `closed=true`, без принудительного GC.
Каждая job получает `included=0`, `tooLarge=1`; следующая маленькая job на том же
manager успешно создаёт одну часть в прежнем cap.

## R4 — резерв partial ZIP

Резерв ZIP учитывается отдельно от числа полностью записанных bytes. После успешного
`reserveDisk()` весь chunk остаётся зарезервированным при short write/ошибке; снять
его можно только после успешного удаления partial. В error cleanup передаётся полный
`zipReservedBytes`, а не только `zipBytes`. Неудачный unlink сохраняет безопасный
over-reservation до последующего lifecycle cleanup; fatal storage policy не менялась.

Regression записывает 8192 B большого ZIP chunk, следующую запись завершает synthetic
`EACCES` и дважды запрещает удаление `.zip.partial`. Job завершается `failed` без
artifacts, partial остаётся размером не менее 8192 B. При scratch quota 1 100 000 B
следующая job с хорошо сжимаемым original 1 085 000 B получает `scratch quota
exceeded`. После успешного terminal-directory cleanup partial исчезает, резерв
освобождается и тот же workload завершается `completed`.
