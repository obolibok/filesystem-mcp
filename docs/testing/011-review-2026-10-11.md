## R1 P2 Отсечение prefix не нормализует начальное dot segment

Место: `src/core/glob.ts:345` и `369–376`, построение prefixes и shouldDescend.

Fixture: `Wanted/a.txt`, `Wanted/nested/b.txt`, оба с текстом token.
Вызовы find_files и search_text с explicit root, pattern `./Wanted/**/*.txt`,
includeIgnored=true, includeHidden=false; у search_text searchPattern=token.
Остальные параметры default. Этот pattern проходит текущую input validation.

| Pattern           | Принятый runtime до 011 | Head 011                                         |
| ----------------- | ----------------------- | ------------------------------------------------ |
| Wanted/**/*.txt   | Оба файла               | Оба файла                                        |
| ./Wanted/**/*.txt | Оба файла               | Пустой результат, isError=false, truncated=false |

Guarded walker перечисляет root и видит Wanted. Однако raw prefix `./Wanted`
не равен relative entry `Wanted` и не проходит startsWith-проверки: нужный
подкаталог не открывается. У прежнего fs.glob начальный `./` был допустим.

Исправить согласованную нормализацию glob и prefix pruning без расширения
доступа или изменения разрешённого glob синтаксиса. Добавить регрессию обоих
MCP tools: эквивалентные шаблоны с/без `./` возвращают те же результаты, а
реальные opens остаются ограниченными maxDepth/limit. Не заменять ошибку
постфильтрацией полного дерева.

## R2 P2 Windows literal prefix потерял прежнюю регистронезависимость

Место: `src/core/glob.ts:350–354` (posix.matchesGlob), `369–376` (prefix pruning).

Та же fixture, фактическое имя папки `Wanted`; pattern `wanted/**/*.txt`.
На проверенной Windows filesystem исходный runtime возвращает оба файла
(пути в результате используют requested spelling wanted). Head 011 возвращает
пустой результат с isError=false/truncated=false у обоих tools.

Сравнение raw prefix с перечисленным именем регистрозависимо; последующий
posix matcher также требует проверки. Прежний native glob разрешал literal
filesystem prefix с другим регистром. Пользователь может видеть папку в list
и затем не найти её содержимое по привычному Windows spelling.

Сохранить фактическую прежнюю семантику Windows literal path segments/aliases
вместе с bounded traversal. Не делать вслепую весь glob case-insensitive:
отдельно проверить wildcard matching и case-sensitive filesystem/Linux.
Регрессии обоих tools должны покрывать literal prefix с другим регистром и
literal filename, а также контроль с совпадающим регистром. Existing canonical
root/8.3 tests не покрывают spelling внутри pattern.
