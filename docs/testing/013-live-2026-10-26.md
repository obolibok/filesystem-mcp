## Источники и версия

- Пользователь сообщил об успешном результате и открыл чат
  «Показ метаданных roots». Планирование прочитало результаты во вкладке:
  snapshot, bundle, сравнение с list_roots и повторные calls после restart.
- Из read_thread были доступны только ссылки на содержимое ответов;
  содержательные результаты проверены в открытом браузере.
- Планирование независимо прочитало только артефакты двух synthetic jobs,
  их job.json, BUILD.json установленного комплекта и sample-source/hello.txt.
  Сверены sizes/SHA-256, ZIP CRC и содержимое; новые jobs не создавались.
- BUILD.json установленного комплекта: sourceCommit
  `431860a1694abbf73d16b0eafbd9df7213e60950`, принятый merge PR #11.
- Реальные paths, hostname, machine UUID, метки и serial томов в Git не сохранены.
  Приведённые ниже IDs и hashes относятся только к synthetic smoke artifacts.

## Restart и границы

Оператор подтвердил restart сервиса. В чате после этого выполнены job_status
прежнего bundle jobId и get_artifact прежнего manifest artifactId, без нового
snapshot/bundle. Полученный manifest размером 2448 B сохранил SHA-256 и provenance;
локальная независимая сверка подтвердила тот же файл. Само закрытие/запуск
PowerShell планирование не наблюдало; время выхода по Ctrl+C не измерялось.

После restart целевой клиент повторно запросил именно bundle manifest.
Повтор ZIP и snapshot manifest после restart в этом пользовательском прогоне
не утверждается; их локальный packaged restart smoke описан в интеграции.

Это малый synthetic smoke с одним файлом, а не новый большой обход. Сетевая
проверка относится к metadata UNC/RaiDrive; snapshot/bundle строились по локальному
sample-source. Отдельный SMB server, Windows 11/VM, сетевой snapshot/bundle и
уникальность/неизменность идентификаторов других провайдеров здесь не проверялись.
Рабочие inventories и оригиналы предприятия не сохранялись в Git.
