## Teardown

Перед остановкой все три jobs имели terminal state; незавершённых jobs не было.
По просьбе пользователя tunnel некоторое время оставался idle, затем завершился
нормально после одного `Ctrl+C`. Независимая проверка зафиксировала:

- owned process exited;
- `/readyz` недоступен;
- force termination не применялась;
- результат `GRACEFUL_STOP_PASS`.

Таким образом, зависание в `stopping`, наблюдавшееся в опыте 003, в этом запуске
не воспроизвелось. Один успешный teardown не доказывает устранение прежней причины.
Synthetic fixture, scratch, profile и client evidence оставлены локально для
приёмки; чужие процессы/профили не изменялись.
