## R1 — P1: scratch доступен как источник и обходит source policy

Место: `src/core/bundle-pipeline.ts:153-156`, `src/tools/bundle.ts:140-141`.

Root-only `assertScratchSeparated` допускает scratch внутри source root: snapshot
исключает его при обходе. Bundle не проверяет выбранный requested/resolved path
через `isScratchPath` перед `openOriginal`, поэтому может читать служебные ZIP/JSON.

Воспроизведение через public MCP:

1. Разрешить synthetic root с подкаталогом scratch; собрать `original.bin`.
2. Перезапустить сервер с тем же scratch и `FS_DENYLIST=original.bin`.
3. Старые job_status/get_artifact теперь запрещены, как и требуется.
4. Заказать новый bundle с selector `scratch/<oldJobId>/<oldPartId>.zip`.

Новая job возвращает `completed`, `complete=true`, included=1 и успешно доставляет
старый ZIP внутри нового. Запрет источника обходится через сохранённые bytes.

Исправление: запрещать каждый выбранный requested и resolved source внутри scratch
до открытия/захвата bytes. Проверить storage вложенный в root, canonical/8.3 aliases,
metadata и готовые artifacts. Policy failure должен быть fatal, без новых доступных
частей. Не расширять allow-list для служебных файлов.

## R2 — P1: ошибка ZIP input аварийно завершает весь сервер

Место: `src/core/bundle-pipeline.ts:336-350`.

`ZipFile` не имеет обработчика `error`. `yazl.addFile` сообщает ошибки stat/read
на этом emitter, а catch вокруг async iteration output их не перехватывает.
В snapshot producer уже есть перенаправление таких ошибок в output.

Воспроизведение: после capture удалить только собственный synthetic spool через
beforeCompress hook. Отдельный Node-процесс завершился exit 1 с
`Unhandled 'error' event`, `ENOENT`, emitter `ZipFile`, `yazl/index.js:36`.
Job не достигает штатного failed/cleanup; остальные jobs endpoint тоже теряют процесс.

Исправление: связать ошибки ZIP и source streams с Promise producer и lifecycle
ошибкой, закрывать ресурсы на всех путях. Regression должен доказать failed job,
недоступность partial artifacts и способность того же сервера выполнить следующую job.

## R3 — P2: превышение ZIP cap оставляет открытый source stream

Место: `src/core/bundle-pipeline.ts:373-376`.

`output.destroy()` не закрывает внутренние read/compression streams, созданные
`addFile`. При oversized это штатный путь алгоритма split, а не редкое исключение.

Воспроизведение: 8 MiB poorly-compressible original, допустимый ZIP cap 64 KiB.
Job завершилась `completed` с `too_large`. После manager.close и ещё 200 ms source
ReadStream оставался `closed=false`, `destroyed=false`, `readableEnded=false`,
bytesRead=327680, readableLength=65536. Закрылся только после явного test-only destroy.
Оба независимых запуска дали тот же результат.

Исправление: управлять source/compression streams и их завершением при cap/split,
cancel и error. Проверить несколько oversized/split jobs подряд, возврат handles и
буферов к baseline и cleanup scratch; не ограничиваться проверкой terminal state.

## R4 — P2: ошибка служебного storage маскируется под недоступный оригинал

Место: `src/core/bundle-pipeline.ts:299-310`.

Общий catch охватывает source read вместе с scratch write/close/removeTemp, а затем
классифицирует EACCES/EPERM как recoverable source outcome. Ошибки cleanup местами
поглощаются. Это нарушает разделение per-file пропусков и fatal storage failure.

Инъекция EACCES именно в scratch output.write при доступном original дала
`completed`, complete=false, inaccessible=1 и опубликованный manifest. Требуется
failed storage error без доступного частичного комплекта.

Исправление: ограничить recoverable классификацию операциями над source. Для scratch
write/close/delete проверять fatal state, корректную retained-byte quota и повторный
cleanup. Новому producer нужны собственные I/O fault tests; старый snapshot suite
не покрывает его catch paths.

## R5 — P2: idempotent reuse обходит текущую авторизацию статуса

Место: `src/tools/bundle.ts:180-191`.

Manager возвращает prior job по key/fingerprint без guard, а handler немедленно
публикует jobStatusValue. В отличие от job_status/get_artifact, выбранные сохранённые
пути при этом не проходят текущую policy.

После restart с `FS_DENYLIST=original.bin` обычные status/fetch дали ошибку, но
повтор bundle с прежним key и selection вернул reused=true, state=completed и два
artifact summaries. Это disclosure статуса/metadata; самостоятельная выдача bytes
данным путём не наблюдалась. Обход bytes из R1 — отдельный дефект.

Исправление: перед возвратом reuse применять ту же текущую авторизацию root и
сохранённых requested/canonical paths, что у status/fetch. Добавить regression
narrowing с restart и без него; не отменять immutable repeat после обычного удаления
исходного файла при сохранённых правах.

## R6 — P2: bundle не соблюдает общий лимит чтения originals

Место: `src/core/bundle-pipeline.ts:182` и bounded open в `src/core/fs.ts`.

Effective source limit учитывает только maxBundleFileBytes/maxBundleRawPartBytes.
FS_MAX_FILE_SIZE применяется к закрытым ZIP/manifest, но не к исходнику, в отличие
от get_file и требования карточки сохранить general-file limits.

Public MCP repro: FS_MAX_FILE_SIZE=1048576, compressible original 2097152 B.
get_file вернул TOO_LARGE; bundle — completed/complete=true, sourceBytes=2097152,
ZIP 2217 B; get_artifact успешно выдал архив. Это не проверка с невалидным env:
1 MiB — допустимый минимум общей настройки.

Исправление: учесть general-file cap в effective source limit, сохранив независимый
delivery cap. Хорошо сжимаемый файл может превышать именно delivery cap, но не общий
source cap. Иное поведение требует явного согласования изменения контракта; в этом
review оно не принято. Добавить обе проверки, чтобы не запретить допустимое сжатие.

## R7 — P2: junction с отсутствующим leaf не отвергается как unsafe selector

Место: `src/core/fs.ts:426-427`.

Проверка isSymlink выполняется только после успешного realpath. Если файл под
junction отсутствует, NOT_FOUND классифицируется producer как обычный missing.

Synthetic `source/alias` — настоящий junction в другой allowlisted root.
Выбор `[kept.bin, alias/missing.bin]` дал completed, included=1, missing=1 и ZIP.
Новая утечка bytes этим примером не доказана, но это нарушение явного no-follow /
fatal-unsafe контракта: добавление второго root в allow-list не разрешает selector.

Исправление: проверять существующие компоненты относительного пути независимо от
существования leaf. Сохранить missing для обычного отсутствующего файла; unsafe
junction/symlink должен завершать весь запрос/job без частичного пакета.

## R8 — P2: локальный harness может записать результат внутрь source через alias

Место: `scripts/bundle-check/local-mcp-check.mjs:64-68`.

Fixture root canonicalized, а delivery/scratch проверяются только лексическим
relative до mkdir. Existing junction либо Windows short spelling позволяет обойти
assertOutside. Этот дефект относится к локальному harness, не к public tool.

На свежем synthetic stand создать внешний delivery-alias junction в source и
передать его как --delivery-dir. Harness завершился exit 0 и записал непосредственно
в source `bundle-manifest.json`, `bundle-00001.zip`, repeat и local report.
Таким образом, заявление о неизменности source неверно для разрешённого harness input;
существующие одноимённые файлы могли бы быть перезаписаны.

Исправление: canonicalize существующий target либо ближайшего существующего ancestor
и проверить итоговое containment до любых mkdir/write. Использовать подход уже
проверенного originals-delivery harness; добавить realpath/8.3/junction negative cases
с assertion, что source и output не изменились после отказа.
