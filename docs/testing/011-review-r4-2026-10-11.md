## Закрытие R4

Для comma brace patterns общий depth bound теперь консервативно использует
пользовательский maxDepth (default/cap 100). Глубина каждой раскрываемой ветви
по-прежнему вычисляется лениво и ограничивается этим bound; finite patterns
сохраняют точный cutoff. Не требуется раскрывать Cartesian product заранее.
Non-brace оптимизация не менялась, PathGuard/no-follow и cancellation сохранены.

Независимо повторены реальные MCP probes из предыдущих review, baseline —
фактический source planning main после 010; до этого review main менял только docs:

- Spelling/brace matrix: 30 сравнений — 26 успешных поисков с одинаковыми наборами
  файлов и четыре одинаковых отказа validation для запрещённого pipe в extglob.
  Отказы не считаются доказательством поддержки такого extglob.
- Brace-produced globstar matrix: 14 сравнений, все успешны, различий нет.
- Depth matrix: 18 сравнений, оба tools, три patterns, maxDepth=0/1/2;
  результаты совпадают, ложного truncated=false при потере файлов больше нет.

В частности, при maxDepth=2 и при omitted default patterns `**/file.txt`,
`{*,x}*/file.txt` и `{*,x}{*,y}/file.txt` возвращают a/file.txt и a/a/file.txt.
При depth=1 остаётся только a/file.txt, при 0 — пусто. Вариант `{*,x}*/b.txt`
теперь находит Wanted/nested/b.txt. Прежние R1–R3 dot/case/brace controls проходят.

Сравнение raw outputs первоначально ошибочно требовало успеха и от четырёх
запрещённых pipe controls; исправлен только диагностический comparator, затем
повторно разобраны те же ответы. Runtime не менялся, повторного обхода для
маскировки failure не было; фактический outcome — одинаковые validation errors.

Новые постоянные tests дополнительно проверяют actual directory opens,
ignore reads, hidden/ignored policy, limit=1/100, отсутствие N+1 read, finite
branch pruning и закрытие handles при отмене во вложенном unmatched traversal.
Они пройдены как в полном check, так и в actual 8.3 TEMP suite.
