1. Инвентаризация/индекс направлены на snapshot, targeted name search — на
   find_files, content search — на search_text. Известный root не требует
   широкого предварительного поиска; multiple roots требуют явного scope.
2. Проверено разделение scanWarning/pageTrailer во всех местах вызова.
   Предупреждение предшествует rows на каждой collected page, включая final;
   list продолжает использовать прежний position/cursor trailer. Пагинация
   воспроизводит сохранённый набор, не продолжает остановленный scan.
3. Общий warning не перенаправляет content search на snapshot. Resource/cursor,
   relative paths и metadata сохраняются. Реальный search_text regression
   проверяет 10001 matches, cap=10000, externalized resource и final page.
4. Job status остался без собственного text: JSON text и structuredContent
   доступны модели. Локальная регрессия проверяет complete/partial walk,
   точные counters, manifest и старый interval при completed reuse.
5. Описания разделяют completed и complete, предварительные progress counters,
   область/исключения и возраст результата. Не обещается atomic индекс всех
   физических файлов; inaccessibleSkipped не складывается с filesWritten.
6. Самостоятельно сняты actual tools/list базового main и reviewed head через
   synthetic SDK clients для full/read-only. Побитовое сравнение JSON полей
   tools после исключения description подтвердило неизменность contracts:
   names/count, titles, input schemas/defaults, annotations, outputSchema policy.
   Различаются только find_files, snapshot и job_status descriptions.
