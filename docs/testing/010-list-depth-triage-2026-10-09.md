# 010: list обходит дерево глубже запрошенного, 09.10.2026

Проверенный main: `e8de76846eda44c1db8a27aa4c4fcb6fce1b54d7`.
Среда: Windows, Node v24.15.0. Runtime не менялся.
Пользователь подтвердил, что установлен последний комплект; точный SHA
установленного процесса отдельно не снимался.

## Наблюдение

Пользовательский скриншот показывает повторный TIMEOUT для list с maxDepth=1,
maxEntries=100, includeHidden=true, includeIgnored=true. Другие инструменты
отвечали. Скриншот содержит отчёт модели, а не сырой transport trace.
Исходный путь и сам скриншот в Git не включены.

## Подтверждённая причина

- `src/tools/list.ts`: collect вызывает globEntries с pattern='**/*' и
  maxDepth=args.maxDepth-1. maxEntries передаётся только в paginate.pageSize;
  накопление ограничивает MAX_LIST_ENTRIES, но обход продолжается ради totals.
- `src/core/glob.ts`: processDirentMatch проверяет глубину после получения
  match от fs.glob. В processGlobPattern ограничение глубины в fs.glob не
  передаётся и descent не обрезается.
- AbortSignal используется при загрузке ignore rules, но не проверяется
  внутри основного processGlobPattern. Если вложенные matches отбрасываются
  по глубине, caller долго не получает управление для проверки отмены.
- При skipIgnored=true GitignoreManager.load отдельно ищет '**/.gitignore'
  по дереву до основного обхода. Это соседний путь лишней работы, который
  также нужно ограничить. На пользовательском вызове includeIgnored=true,
  поэтому этот preload не является причиной именно показанного сбоя.

## Синтетическое воспроизведение

В изолированном synthetic root создать три branch-папки, в каждой десять
nested-папок, в каждой nested — два маленьких текстовых файла. Верхний уровень
содержит только три папки; всего 33 папки и 60 файлов.

Через настоящий in-memory MCP client/server вызвать list с приведёнными выше
параметрами. Инструментировать fs.promises.glob до импорта сервера, синхронизируя
ESM exports: считать настоящие raw matches только для synthetic cwd, включая
отфильтрованные по глубине. Windows cwd сравнивать без учёта регистра.
Для harness явно задать FS_SNAPSHOT_DIR на отдельный synthetic scratch вне
source до создания сервера; не использовать рабочий scratch или туннель.

- Без задержек: ответ успешен, entryCount=3, totalEntries=3, около 54 ms.
  Движок перечислил 93 raw matches, из них 90 глубже нужного уровня.
- Контролируемая задержка 15 ms перед выдачей каждого глубокого raw match,
  FS_SEARCH_TIMEOUT_MS=1000: ответ TIMEOUT через 1591 ms, те же 93 matches.
  После условной границы 1000 ms обработаны ещё 34 matches. Указанное время
  отсчитывалось от начала client call; это не точное время внутреннего timer.

Задержка второго опыта искусственная: это проверка механизма отмены, не замер
производительности большого диска. Первый опыт независимо доказывает лишнюю
рекурсию на настоящем дереве. Файлы предприятия и установленный сервис не
использовались. Локальный probe не является обязательной зависимостью задачи:
структура, способ измерения и результаты полностью описаны здесь.

## Направление исправления

Ограничить descent до входа в более глубокие каталоги, загружать ignore rules
только для действительно посещаемой области, проверять отмену во время обхода
и закрывать iterator/handles. Разделить размер страницы и лимит собираемого
набора; после достижения лимита прекратить обход и честно показать неполноту.
