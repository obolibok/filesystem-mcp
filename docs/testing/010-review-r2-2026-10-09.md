## R3 — P2: тесты не учитывают Windows 8.3 путь TEMP

Три падения в `__tests__/list-bounded.test.ts`:

1. `cancellation during ignore loading...`, строка 516: Missing expected rejection.
   До assertion предупреждение о невозможности прочитать .gitignore: root передан
   через короткий alias, openOriginal ожидает canonical root. Mock не доходит до
   abort, тест не создаёт предполагаемую ситуацию отмены.
2. `list respects nested ignore negation...`, строка 601: observed.opened содержит
   относительные пути через `../../...` вместо пустой строки / nested / .hidden.
3. `list wire deadline...`, строка 626: такой же mismatch opened root; сам TIMEOUT
   и исправленный R2 hint возвращены правильно.

Общая причина в setup/instrumentation: fixture возвращает сырой createTestRoot(),
а instrument вычисляет relative от него. Windows runner задаёт TEMP коротким 8.3
путём, тогда как публичный list использует canonical путь. Прямой walker-test
также не воспроизводит canonical root, который передаёт production tool.
Это не прежний flaky PowerShell helper; повтор неизменённого CI не запускался.

Независимое локальное воспроизведение на reviewed head: создать synthetic temp
parent с длинным именем, получить ShortPath через Scripting.FileSystemObject,
передать его в TEMP и TMP только дочернему процессу, выполнить:

```powershell
node --test --import tsx --test-name-pattern="cancellation during ignore loading|list respects nested ignore|list wire deadline" __tests__/list-bounded.test.ts
```

Получены **0 pass / 3 fail / 0 skips**, ровно те же warning/assertions, что в CI.
С обычным TEMP полный check проходит. Junction TEMP дополнительно вызывает
предусмотренный отказ scratch; это отдельный control, а не точная замена 8.3.

Исполнителю в том же coding thread переданы причина, воспроизведение и logs IDs.
Требуется canonical setup/согласованные измерения, сохранение meaningful abort
и handle assertions, проверка реальных alias roots через public MCP. Не ослаблять
PathGuard/no-follow, не добавлять skip и не увеличивать timeout. Подтверждённого
нового runtime-дефекта публичного list этим CI не установлено. После fix — тесты
с обычным и коротким TEMP, полный check, новый SHA и повтор CI.

## Живой опыт после закрытия R3 и зелёного CI

Оператор останавливает прежний экземпляр и сохраняет его config.json и нужный
scratch. Новый комплект распаковывает целиком, переносит настройки и запускает
Check.ps1, затем Start.ps1 по README внутри поставки. Один scratch и один tunnel_id
не должны одновременно использоваться старой и новой копиями. Не заменять runtime
поверх работающей установки. BUILD.json должен показывать reviewed SHA выше.

После обновления подключения/каталога tools ожидаются limit и pageSize вместо
maxEntries. Полный [live-протокол проверенного head](https://github.com/obolibok/filesystem-mcp/blob/29fa8b7b2bc20371a0a7fd50e7c9e3b87798f2ef/docs/testing/010-bounded-list.md)
содержит small/full/partial, mismatch и resource сценарии. Основной повтор бага:

> Возьми нужный большой разрешённый root из list_roots. Вызови list с явным path,
> maxDepth=1, includeHidden=true, includeIgnored=true, limit=100, pageSize=25.
> Покажи время, entryCount, totalEntries, limit, truncated и stoppedReason.
> Если есть Next page, исполняй именно JSON из этой строки до последней страницы,
> без восстановления параметров вручную. Проверь отсутствие повторов, суммарно
> не более 100 записей и сохранение предупреждения о лимите на последней странице.
> Повтори с includeIgnored=false. Не запускай snapshot в рамках этой проверки.

Листать нужно без пауз: cursor/resource cache по-прежнему около 60 секунд.
Отдельно сменить только pageSize между pages и проверить малую выборку ниже limit.
Сохранить обезличенный итог; личные paths и inventories в Git не включать.

Остаточные ограничения: exact N консервативно truncated; сортируется собранный
набор, не глобально всё дерево. Limit считает файлы и папки вместе, не ограничивает
число исключённых policy записей или OS calls. Начатое зависшее OS I/O нельзя
принудительно прервать. SMB, Windows 11/VM и целевой ChatGPT требуют своего live.
