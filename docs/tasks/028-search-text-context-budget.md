# 028 — Бюджет контекста `search_text`

Статус: active. Ветка: `codex/028-search-text-context-budget`.

## Контракт

Длинные строки числовых измерений в .mbt могут занимать десятки тысяч символов
на одно совпадение. В Open WebUI исходный ответ на limit: 60 достиг 263 647
символов и следующий запрос не поместился в окно vLLM.

- На совпадение возвращать до 500 Unicode-символов фрагмента с исходного места,
  в том числе в конце длинной строки. Сохранить короткую строку целиком,
  исходный путь, номер строки и позицию. Обозначить обрезанные края и обрезку
  самого совпадения. Соседние строки при context также ограничить.
- Ограничить данные каждой выдачи 16 384 байтами UTF-8. Учесть пути, метки,
  соседние строки, диагностику и курсор. Служебная обёртка JSON-RPC находится
  вне бюджета. Сокращать соседний контекст первым, затем выдавать только
  поместившиеся записи. Сохранять валидный текст и формат MCP.
- limit управляет сбором совпавших строк, pageSize — верхней границей числа
  строк на странице. Следующая страница начинается с первой невыданной записи.
  Курсор листает собранные записи. Тайм-аут скана по-прежнему явно виден.
  Аргументы вызова не увеличивают ограничения.
- Сохранить поиск по .mbt, правила доступа и переход к исходной строке через
  read или к исходному файлу через get_file. Обновить справку MCP и reference.
  Суммарный бюджет нескольких вызовов WebUI вне scope.

## Приёмка

- Синтетические .mbt: девять строк по ~29 000 символов, короткие .txt, поиск
  9160 с limit: 60. Проверить обе группы, фрагменты и байтовый бюджет.
- limit: 1, совпадение в конце. Проверить исходные координаты, read/get_file,
  а также короткую строку целиком.
- Кириллица, немецкие символы и длинные соседние строки. Проверить Unicode
  и UTF-8, включая совпадение длиннее окна.
- Большой pageSize и несколько страниц: собрать все записи без пропусков
  и новых дублей. Отдельно проверить частичный скан по тайм-ауту.
- Локальные проверки и Windows portable Verify. После них повторить сценарий
  в тестовом Open WebUI с моделью Flash и проверить, что следующий запрос
  модели проходит и она завершает ответ.

## Work record

База `7cb76702ff6fca49ff3a21faca442295a9ffd2f0`, ветка
`codex/028-search-text-context-budget`.

- Синтетическое воспроизведение через MCP на базе, девять .mbt по 29 000
  символов и два коротких .txt, дало 261 211 байт, а одиночный матч в конце
  строки при `limit: 1` дал 29 256 байт. После изменения локальный stdio smoke
  дал 4 995 и 979 байт соответственно, сохранив 11 совпадений и исходный
  столбец 28 996 для одиночного матча.
- Формат grep сохраняет путь и номер строки и добавляет исходный столбец
  в UTF-16 с нуля. Фрагмент содержит до 500 Unicode code points. Метки в
  тексте и `_meta` показывают обрезку края и самого совпадения. Соседние строки
  тоже ограничены, а при нехватке места уменьшается радиус контекста.
- Бюджет применяется к UTF-8 тексту и учитывает необязательный resource link.
  Курсор продвигается ровно на число выданных совпадений. Обычный `Next page`
  повторяет аргументы. Для длинного запроса сервер выдаёт исполняемый JSON с
  курсором и `pageSize`, восстанавливает запрос из того же снимка и проверяет
  его scope через текущий PathGuard. При повторе полных аргументов
  несовпадающий запрос отклоняется. Предупреждение о limit или тайм-ауте
  сохраняется на каждой частичной странице.
- JSON resource первой страницы содержит собранные фрагменты, когда помещается
  в действующий лимит ResourceStore. Продолжения доступны и для большего
  результата. Для рекурсивных путей сверх максимального байтового размера
  аргумента read/get_file модельный текст показывает имя файла с меткой, а
  `_meta` сохраняет точный путь.
- Длинный экранируемый запрос до 10 000 UTF-16 units на базе мог дать 20 347
  байт только в JSON продолжения. Короткий курсор покрыт тестами, включая
  чужой инструмент и сужение scope. Невалидный RE2 с объёмной диагностикой
  покрыт через MCP. В stdio smoke ошибка ограничена 16 128 байтами с прежним
  кодом и меткой обрезки.
- Локальные регрессии проверяют .mbt/UTF-8, короткие строки, RE2, чтение линии и
  byte-exact get_file, контекст, порядок и полноту страниц, частичный результат
  по реальному дедлайну и штатный отказ после сужения доступа.
- Windows, Node 24.15.0 и npm 11.12.1. `npm ci` прошёл, целевой MCP прогон
  прошёл 20 из 20. `npm run check` прошёл build, проверку типов, ESLint,
  Prettier, Knip и тесты (609 passed, 0 failed, 13 skipped). Пропуски связаны
  с POSIX-only условиями и недоступными file symlinks на Windows.
  `git diff --check` прошёл. Локальный результат готов к ревью.
- Portable Verify и тестовый Open WebUI с моделью Flash входят в отдельную
  приёмку после ревью.
