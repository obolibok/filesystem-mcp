# Проверка 014: snapshot_tree на настоящем хранилище

Эксперимент добавляет отдельный tool snapshot_tree. Обычный snapshot продолжает
выдавать прежний CSV. В tree сохраняются файлы и каталоги, включая пустые;
повторяющиеся пути заменены числовой глубиной и именем. Оригиналы файлов оба tools
не читают: это снимки метаданных, а не содержимого.

## Обновление

1. Остановите прежний Start.ps1 через Ctrl+C и дождитесь выхода. Сохраните прежнюю
   папку, config.json и data/jobs. Распакуйте весь новый комплект в отдельную папку.
2. Перенесите tunnelId, roots и нужные limits в новый config.json. Не копируйте
   старый config целиком без проверки: для эксперимента нужно поле
   `"experimentalSnapshotTree": true`. В опытном комплекте 014 оно уже включено;
   в обычном шаблоне поставки значение по умолчанию false.
3. Проверьте scratchDirectory: он должен быть вне исследуемых каталогов.
   Относительные пути считаются от папки нового комплекта. Для сохранения прежних
   jobs перенесите весь scratch после остановки обоих процессов; не запускайте
   две копии с одним scratch или tunnel. Для A/B старые jobs не нужны.
4. Из папки нового комплекта запустите:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\Check.ps1
   powershell -NoProfile -ExecutionPolicy Bypass -File .\Start.ps1
   ```

   Check должен показать LOCAL_MCP_PASS и 14 read-only tools, включая snapshot
   и snapshot_tree. Введите прежний runtime API key скрыто. Подключение туннеля
   описано в README.md / README.html. Обновите discovery tools в ChatGPT, если
   snapshot_tree не появился; после изменения config нужен перезапуск сервиса.

## Два снимка одного каталога

Начните с небольшого стабильного каталога, содержащего файлы, вложенные и пустые
папки. Затем повторите на большом каталоге/сетевом хранилище. Два обхода идут
последовательно; изменения файлов между ними могут дать законные расхождения.
Не запускайте сразу весь диск ради проверки нового формата.

В ChatGPT укажите нужный каталог вместо `<каталог>`:

```text
Проверь наличие snapshot и snapshot_tree в инструментах, затем вызови list_roots.
Выбери разрешённый root для <каталог>; не угадывай путь. Покажи фактический path,
который будет одинаковым для обоих снимков. Сначала вызови обычный snapshot с
этим path, includeHidden=false, includeIgnored=false, forceRefresh=true и новым
уникальным idempotencyKey для stable. При сетевом повторе используй те же аргументы
и тот же ключ. Дождись completed через job_status, затем получи manifest и все
ZIP-части через get_artifact. Не считай snapshot строковым листингом.
Сохрани jobId, elapsedMs, complete, counters и manifest для сравнения.

Теперь вызови snapshot_tree с тем же path и теми же includeHidden/includeIgnored,
forceRefresh=true, но отдельным новым уникальным idempotencyKey для tree.
При повторе сохрани именно этот ключ. Также дождись completed, получи manifest
и все ZIP-части через get_artifact. Покажи оба фактических jobId и оба формата.
```

Если первый snapshot ещё строится, продолжайте job_status его jobId. Новый вызов
snapshot с новым ключом создаст лишний обход. Для большого диска сервис может
работать дольше одного ответа ChatGPT: продолжайте опрос в следующем сообщении.
При failed/expired сначала сохраните статус/ошибку; успешную выдачу не объявляйте.

## Проверка полученных файлов

Отправьте после получения всех частей:

```text
Проверь байты полученных файлов в среде анализа, не делай вывод только по тексту
ответов MCP. Сверь SHA-256 каждой ZIP-части с соответствующим manifest, проверь
CRC при распаковке, rawBytes/zipBytes и число частей.

Stable CSV разбирай по его manifest. Tree manifest должен иметь schema
filesystem-mcp.snapshot-tree-manifest, version=1, layout=tree-depth-v1.
Каждый tree CSV содержит первой логической CSV-записью фактический абсолютный
исходный путь в одном поле, затем Type,Depth,Name,Length,LastWriteTime.
Используй CSV parser: кавычки, запятые и переводы строк внутри имени допустимы.
Depth=0 означает непосредственных детей исходного пути, а не корень диска.
F — файл, D — каталог, C — контекст предков в начале части, U — отметка неполного
обхода каталога. C/U не являются новыми объектами. Length и LastWriteTime у
каталогов/служебных записей пусты. Восстанавливай относительные пути по стеку
каталогов и числовой глубине, каждую часть начинай с её собственного root/context.

Сравни множества файлов: RelativePath, Length, LastWriteTime стабильного формата
с восстановленными путями, Length, LastWriteTime записей F. Учитывай согласованный
разделитель путей; не меняй регистр или символы имени. Отдельно проверь пустые
папки по D. Не сравнивай общее число CSV-записей с числом файлов: tree rows
включает root/header/D/C/U. При complete=false или U покажи причины неполноты.

Дай таблицу stable/tree: filesWritten, directoriesWritten (для tree), complete,
ошибки/пропуски, rawCsvBytes, zipBytes, parts, elapsedMs. Рассчитай экономию ZIP
и raw в процентах. Покажи только итог и расхождения, не печатай весь инвентарь.
```

Ожидается совпадение файлов и их метаданных на неизменном каталоге; tree дополнительно
показывает папки. Выигрыш размеров зависит от структуры и имён. Ускорение обхода
и уменьшение RAM не гарантируются. Snapshot не является атомарным снимком диска.

## Перезапуск и отключение эксперимента

Сохраните tree jobId, manifest artifactId и SHA-256. Остановите и повторно
запустите сервис с тем же scratch: прежние job_status/get_artifact должны работать
без нового обхода. Затем при желании задайте experimentalSnapshotTree=false и
снова перезапустите. Snapshot_tree исчезнет из discovery, а обычный snapshot и
чтение ещё не истёкших tree-результатов сохранятся.

## Что прислать для приёмки

Достаточно sourceCommit из BUILD.json, двух jobId, таблицы сравнения, результата
проверки SHA/CRC/совпадения файлов/пустых папок и restart, выхода по Ctrl+C.
При ошибке нужны фактические аргументы, статус и сообщение. Рабочие инвентари,
пути, UUID/serial и ключи остаются локально; в Git сохраняется обезличенный итог.
