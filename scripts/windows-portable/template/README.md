# Schwarzbeck MCP — переносимый комплект для Windows

Сборка для Windows 10/11 x64. Внутри уже есть Node.js, собранный filesystem-mcp,
production-зависимости и полный tunnel-client с cloudflared и лицензиями.
Устанавливать Git, Node, npm, Python или компилятор на целевую машину не нужно.
Версии, source commit и hashes записаны в BUILD.json и SHA256SUMS.json.

Откройте этот файл или README.html. Все команды ниже выполняются из папки комплекта.
Используется встроенный Windows PowerShell 5.1; администратор для обычного запуска
не нужен. Комплект проверен на Windows 10 Pro x64 (19045), включая PowerShell 5.1.
Windows 11 и конкретную VM следует проверить по шагам ниже; ARM64/32-bit не входят
в эту сборку.

## 1. Распаковка и первая локальная проверка

Распакуйте весь комплект, например в C:\SWB-MCP. Не запускайте файлы внутри ZIP.
Можно перенести всю папку в другой каталог; пробелы и Unicode в пути допустимы.
Папка должна быть доступна текущему пользователю на запись.

Откройте PowerShell и выполните:

```powershell
Set-Location 'C:\SWB-MCP'
powershell -NoProfile -ExecutionPolicy Bypass -File .\Check.ps1
```

Ожидается LOCAL_MCP_PASS и 13 read-only tools, включая snapshot, bundle,
job_status, cancel_job, get_artifact и get_file. По умолчанию открыт только
маленький sample-source. Проверка не соединяется с OpenAI и использует отдельный
временный scratch, не изменяя сохранённые jobs рабочего сервера.
ExecutionPolicy Bypass действует только на этот запуск, не меняет политику системы.

## 2. Разрешённые каталоги, несколько дисков и сеть

Откройте config.json в Блокноте. В roots перечислите существующие каталоги:

```json
"roots": [
  "D:/Technik",
  "E:/Daum",
  "//fileserver/production/Inoplacer"
]
```

Это фрагмент для замены поля roots, а не весь JSON. Сохраняйте остальные поля.
В JSON удобны прямые слеши. Для обратных слешей нужно экранирование:
"D:\\Technik". Путь "./sample-source" считается от папки комплекта.
Точки с запятой в названиях корней этот launcher не поддерживает.

Можно указать корень диска "D:/", если нужен весь диск. Предпочтительнее конкретные
каталоги: сервис получит только перечисленные деревья. Буквы дисков на VM должны
соответствовать её дискам; перенос комплекта не переносит сами исходники.
Для сетевых ресурсов лучше UNC, чем подключённая буква диска: доступ проверяется
от имени пользователя, запустившего PowerShell. Его Windows/SMB-права сохраняются.

Launcher одновременно задаёт roots и FS_ROOT_BOUNDARY с тем же списком. Поэтому
запрос клиента на добавление другого корня не расширит разрешённую область.
Глобальные FS_* переменные другой установки игнорируются. Сервер всегда запускается
с --read-only; встроенные исключения чувствительных путей остаются включены.

Исходники должны находиться вне папки комплекта, кроме synthetic sample-source.
Scratch не должен пересекаться с исходниками даже через junction/8.3 alias.
Если открываете весь D:/, разместите комплект и scratch на другом диске.

После изменения config.json остановите сервер и запустите заново, затем проверьте
list_roots в новом чате. При нескольких roots передавайте явный path нужного корня
в snapshot/search/list; для bundle выбирайте файлы в рамках его source path.

## 3. Создание туннеля и runtime API key

1. Войдите в нужную Platform organization:
   https://platform.openai.com/settings/organization/tunnels
2. Создайте туннель, например SWB-filesystem-VM. Проверьте привязки к Platform
   organization и целевому ChatGPT workspace. Скопируйте tunnel_id.
3. В config.json замените пустое tunnelId на полученное значение:
   "tunnelId": "tunnel_..."
4. Создайте отдельный runtime API key:
   https://platform.openai.com/settings/organization/api-keys
   Сохраните ключ в своём менеджере паролей. Его principal должен иметь Tunnels
   Read + Use. Для создания/изменения туннеля нужны Read + Manage.
   Названия элементов интерфейса могут меняться; при отсутствии доступа проверьте
   organization и роль у её администратора.
5. Ключ вводится скрыто при каждом запуске Start.ps1. В config.json, YAML, команду,
   скриншот или переписку его не вставляйте. Admin API key для запуска не нужен.

Правильный tunnel_id не заменяет runtime key. Это также не FS_API_KEY: наш MCP
запущен через stdio, локального публичного HTTP endpoint и отдельного MCP API key нет.
Туннель использует исходящее HTTPS; для обычного подключения требуется доступ
к api.openai.com:443. Входящий порт на роутере открывать не требуется.
Корпоративный proxy/CA/mTLS может потребовать настройки сетевым администратором;
проверка сертификатов не отключается.

## 4. Запуск сервера вместе с туннелем

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start.ps1
```

Введите runtime key в скрытый prompt. Скрипт проверит локальный MCP, создаст профиль,
выполнит tunnel-client doctor и оставит tunnel-client работать в текущем окне.
Туннель сам запускает наш сервер через stdio. Отдельно запускать node не нужно.
Не закрывайте окно во время работы с ChatGPT.

Для проверки профиля без запуска постоянного туннеля:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start.ps1 -DoctorOnly
```

Doctor — локальная проверка конфигурации; он не доказывает успешную доставку в ChatGPT.
В другом PowerShell из той же папки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Status.ps1
```

Дождитесь HTTP 200 от /readyz. Скрипт покажет адрес локального /ui.
Порт выбирается автоматически, admin UI доступен только с 127.0.0.1.
Сообщения диагностик видны в окне запуска; постоянный log-файл по умолчанию не создаётся.

## 5. Подключение плагина в ChatGPT

Используйте тот же workspace, который связан с туннелем. Включите Developer mode
в Settings → Security and login, если он ещё не включён; в управляемом workspace
может потребоваться разрешение администратора.

1. Откройте https://chatgpt.com/plugins и нажмите плюс для добавления MCP connection.
2. Имя: Schwarzbeck Files; описание: read-only filesystem, snapshot and originals bundle.
3. В Connection выберите Tunnel и укажите созданный туннель / tunnel_id.
4. Создайте подключение и проверьте обнаруженные tools. Для этой stdio-конфигурации
   собственный OAuth-сервер не настраивается.
5. Откройте новый чат и добавьте подключение через меню инструментов. Для проверки
   содержимого ZIP/XLS в этом чате должна быть доступна среда анализа файлов.

Если туннеля нет в списке: сверяйте workspace association, Platform organization,
Read + Use и состояние Start.ps1/readyz. После изменения набора tools обновите
подключение/метаданные и откройте новый чат.

## 6. Минимальная проверка перед рабочими данными

Начните с default sample-source. Дайте ChatGPT такой запрос:

«Используй Schwarzbeck Files. Вызови list_roots, покажи разрешённые корни.
Прочитай hello.txt. Создай bundle только из hello.txt в этом корне с новым
idempotencyKey. Дождись завершения через job_status; получи manifest и все
ZIP через get_artifact. Материализуй их как файлы, проверь SHA-256 и CRC,
открой ZIP и покажи исходный текст hello.txt. Если файлы не появились в среде
анализа, явно сообщи об этом — URI не считается полученным файлом».

Ожидаются три строки synthetic текста и сохранённый Unicode. Snapshot можно
проверить отдельным запросом: получить manifest/CSV ZIP и увидеть одну строку
hello.txt. После smoke меняйте roots на разрешённые рабочие каталоги и повторяйте
Check.ps1, restart и list_roots. Не запускайте snapshot целого диска для smoke.

## 7. Где лежат промежуточные файлы и сколько они живут

В этом комплекте: <папка комплекта>\data\jobs, задаётся scratchDirectory.
Можно изменить на "F:/SWB-scratch/jobs". Это отдельная служебная область на запись,
которая не выдаётся как source root. Относительный путь переносится с комплектом;
абсолютный нужно проверить на VM.

| Данные / настройка                | Значение комплекта                           |
| --------------------------------- | -------------------------------------------- |
| Завершённые manifest и ZIP        | 24 часа от завершения job                    |
| Проверка истечения TTL            | Каждые 60 секунд при работающем сервере      |
| Удаление terminal job metadata    | После 2 × TTL от finishedAt, обычно 48 часов |
| Общая квота scratch               | 1 GiB                                        |
| Максимальное время выполнения job | 1 час                                        |
| Параллельность                    | 1 running job, до 4 queued                   |
| Snapshot raw bytes / job          | 512 MiB                                      |
| Snapshot raw CSV / part           | 45 MiB                                       |
| ZIP / artifact delivery           | 8 MiB                                        |
| Bundle raw file / raw part        | 64 MiB                                       |
| Bundle raw bytes / job            | 512 MiB                                      |
| Bundle selectors / job            | 1000                                         |

Настройки limits в config.json — числовые bytes и milliseconds. Например,
FS_SNAPSHOT_RESULT_TTL_MS=259200000 означает 72 часа,
FS_SNAPSHOT_SCRATCH_QUOTA_BYTES=4294967296 означает 4 GiB.
JSON не допускает комментариев, единиц "GB" или запятой после последнего элемента.
Неизвестные/неверные значения launcher отвергает до запуска.

Внутри jobs есть metadata job.json, готовые ZIP/manifest и временные bytes
сборки. При отмене/ошибке сервер очищает незавершённые artifacts; при сбое удаления
место остаётся учтено до последующей очистки. Готовые файлы после TTL недоступны,
физическое удаление может задержаться до уборки/завершения активного чтения.
При остановленном сервере таймер не работает: просроченное удаляется после запуска.
Повторное скачивание не продлевает TTL. Существующие jobs сохраняют записанный
resultExpiresAt: изменение TTL не переписывает их срок задним числом.
После restart queued/running jobs помечаются interrupted, готовые результаты
сохраняются до своего TTL. Один scratch принадлежит одному экземпляру сервера.

Размер оригинала 64 MiB не гарантирует доставку: если один файл не помещается
в закрытый ZIP 8 MiB, bundle отмечает соответствующий outcome; сам оригинал
не режется на куски. Лимиты на стороне ChatGPT отдельно зависят от принимающей
среды. Это настройки сервера, а не утверждение о максимальном объёме ChatGPT.

Папка data\tunnel содержит профиль (только ссылку env:CONTROL_PLANE_API_KEY),
PID/health URL и служебный lock, не ключ. Она не очищается по job TTL.
Локальные preflight-* удаляются после завершения проверки; после аварийного
убийства могут остаться. Файлы, уже полученные ChatGPT, не удаляются серверным TTL.
Кратковременные page/resource caches сервера живут отдельно в памяти (~60 секунд).

## 8. Остановка и перенос на VM

Нормально: дождитесь окончания jobs, нажмите Ctrl+C один раз в окне Start.ps1,
подождите до 45 секунд. Status.ps1 должен показать недоступный /readyz.
Если снова зависнет stopping, во втором окне из папки комплекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Stop.ps1 -Force
```

Это аварийная остановка только проверенного PID этого комплекта и его дочерних
процессов. Скрипт не убивает все node.exe/PowerShell на машине. Незавершённые jobs
будут interrupted после restart. При несовпадении PID identity скрипт откажется
останавливать процесс: проверьте его вручную в диспетчере задач.

Для новой VM лучше взять исходный чистый ZIP комплекта. Для переноса текущей
установки сначала остановите её; при необходимости скопируйте всю папку вместе
с data/jobs. Не копируйте работающий scratch и не запускайте две копии на нём.
В config.json поправьте roots/scratch для новой машины. Ключ в архиве отсутствует,
его снова вводите при старте. Профиль пересоздаётся из config.json автоматически.
На новой VM нужны реальные доступы к source/SMB и исходящий интернет.

Не запускайте одновременно старую машину и VM на одном tunnel_id: это могут быть
два исполнителя запросов с разными файловыми корнями. Для параллельной работы
создайте отдельный tunnel_id, runtime key, plugin и отдельный scratch.
Если сохранённые jobs переносились вместе с изменившимися путями/roots,
для исследования создайте новые jobs: старые artifacts повторно проверяются
по текущим разрешениям, перенос пути не переписывает provenance.

## Состав и обслуживание

- config.json — ваш tunnel_id, roots, scratch и лимиты.
- Check.ps1 / Start.ps1 / Status.ps1 / Stop.ps1 — операторские команды.
- runtime — собственный Node, без зависимости от системного PATH.
- server — собранный принятый fork и production dependencies.
- tunnel — полный проверенный release, включая cloudflared и notices.
- scripts — переносимый launcher и локальный MCP preflight.
- sample-source — только синтетический файл для smoke.
- data — локальное состояние; на чистой поставке рабочих данных нет.
- BUILD.json / SHA256SUMS.json — происхождение и исходные hashes поставки.

Это foreground-приложение, не установленная Windows Service. Закрытие окна,
logout/reboot останавливает доступ. Автозапуск от service account — отдельная
настройка после проверки VM. Обновление через npx @latest не применять: это другой
upstream, без обязательных правок нашего fork. Обновляется целиком проверенный kit;
локальную конфигурацию и нужные данные переносят отдельно.

Источники подключения, проверенные 22.09.2026:

- Secure MCP Tunnel: https://developers.openai.com/api/docs/guides/secure-mcp-tunnels
- Plugins: https://developers.openai.com/plugins/deploy/connect-chatgpt
- tunnel-client help quickstart/init/run/doctor, версия 0.0.14.
- Новые официальные tunnel releases: https://github.com/openai/tunnel-client/releases/latest
- Node Windows platforms: https://github.com/nodejs/node/blob/v24.x/BUILDING.md

Конкретный комплект фиксирует проверенные версии, не обновляет бинарники сам.
Полная повторная облачная проверка после переноса на VM выполняется по разделу 6.
