# Проверка сборки 011 + 012

Эта сборка вводит для find_files и search_text раздельные limit и pageSize.
limit ограничивает найденные файлы/совпавшие строки во всём собранном наборе;
pageSize — число результатов на странице. Старый maxResults удалён.
У поиска maxDepth=0 означает только файлы базового каталога, 1 — также дочерние
каталоги; у list нумерация прежняя: 1 означает только содержимое базы.
012 добавляет исследовательский стенд; срок жизни страниц и память сервиса
в этой сборке не перенастраиваются.

## Обновление и запуск

1. Остановите прежний Start.ps1 через Ctrl+C и убедитесь, что он завершился.
   Сохраните прежнюю папку, особенно config.json и data/jobs. Новую сборку
   распакуйте в отдельную папку; не распаковывайте поверх работающей установки.
2. Перенесите настройки tunnelId, roots и limits в новый config.json.
   Проверьте относительные roots/scratchDirectory: они считаются от новой папки.
   Для этого опыта оставьте или добавьте root ./sample-source. Рабочие source
   каталоги не нужно копировать в комплект. Сохранённые jobs можно переносить
   целиком только после остановки прежнего процесса; для synthetic опыта они
   не нужны. Две копии не должны одновременно использовать один scratch/tunnel.
3. В PowerShell из новой папки выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Check.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start.ps1
```

Ожидается LOCAL_MCP_PASS. Введите прежний runtime key скрыто, дождитесь ready.
Подробности настройки туннеля/плагина и ключа — в README.md / README.html.
Не запускайте одновременно старый и новый комплект на одном tunnelId.
4. В ChatGPT начните новый чат с этим подключением. Обновите обнаруженные tools
   в настройках подключения, если оно всё ещё показывает maxResults вместо
   limit/pageSize. Текущий контракт: find_files pageSize default=100,
   search_text default=500, общий limit default/cap=10000.

## Синтетическая выборка

Следующий блок выполняется в PowerShell из папки нового комплекта. Он создаёт
новый каталог только внутри sample-source; если имя уже занято, останавливается.
Скопируйте показанный в конце путь — это R для запросов ниже, без угловых скобок.

```powershell
$fixturePath = Join-Path (Get-Location).Path 'sample-source/search-011'
if (Test-Path -LiteralPath $fixturePath) { throw 'Fixture already exists; use the existing fixture or choose a new empty name.' }
$files = @(
  'root.txt',
  'Wanted/a.txt',
  'Wanted/second.txt',
  'Wanted/nested/b.txt',
  'Wanted/nested/deeper/c.txt',
  'Unrelated/other.txt'
)
$utf8 = New-Object System.Text.UTF8Encoding($false)
foreach ($name in $files) {
  $target = Join-Path $fixturePath $name
  [IO.Directory]::CreateDirectory([IO.Path]::GetDirectoryName($target)) | Out-Null
  [IO.File]::WriteAllText($target, "swb-011-token swb-011-token`n", $utf8)
}
$fixturePath.Replace('\', '/')
```

Здесь 6 файлов, в каждом одна совпавшая строка с двумя occurrences. Сервису
нужен разрешённый root sample-source; перезапуск после изменения config обязателен.
Файлы можно создать перед Start.ps1 или после — новый scan их увидит.

## Запросы для ChatGPT

Сначала отправьте, подставив фактический путь вместо R:

```text
Проверяем файловый MCP. Вызови list_roots и убедись, что путь R разрешён.
Во всех опытах ниже используй именно R, includeHidden=false, includeIgnored=true.
Показывай фактические аргументы и ответ инструмента: totalMatches, limit,
truncated, stoppedReason, nextCursor и относительные пути. Не заменяй вызовы
своим подсчётом и не создавай snapshot, если явно не попрошу.
```

1. Глубина поиска:

```text
Вызови find_files с path=R, pattern="**/*.txt", limit=100, pageSize=100,
maxDepth=0. Затем повтори с maxDepth=1 и maxDepth=2.
```

Ожидается соответственно 1 / 4 / 5 файлов, truncated=false. Для maxDepth=2
самый глубокий Wanted/nested/deeper/c.txt отсутствует. Повтор без maxDepth
должен вернуть все 6.

2. Проверка R1–R4:

```text
Вызови find_files с path=R, limit=100, pageSize=100, maxDepth=2
для каждого pattern: "Wanted/*.txt", "./Wanted/*.txt",
"{wanted,Else}/*.txt", "{./Wanted,./Else}/*.txt",
"**/b.txt", "{*,x}*/b.txt", "{*,x}{*,y}/b.txt".
Повтори те же проверки через search_text с searchPattern="swb-011-token",
isRegex=false и context=0.
```

На обычной Windows FS первые четыре patterns дают Wanted/a.txt и
Wanted/second.txt. Последние три — только Wanted/nested/b.txt.
Все ответы полные. Если включён case-sensitive режим файловой системы,
нижний регистр wanted следует фактическому режиму FS; остальные controls те же.

3. Разделение общего лимита и страницы:

```text
Вызови find_files с path=R, pattern="**/*.txt", maxDepth=100,
limit=3, pageSize=1. Сразу исполни буквальную команду Next page из ответа,
затем ещё раз Next page из следующего ответа. Не теряй остальные аргументы.
```

В собранном наборе ровно 3 файла, по одному на трёх страницах, без дубликатов.
truncated=true, stoppedReason=limit и warning сохраняются до последней страницы;
на последней нет nextCursor. Какие именно 3 файла попадут в subset, заранее
не фиксируется. После них нет команды продолжения обхода: для большего набора
нужен новый запрос с большим limit. Страницы нужно запрашивать без долгой паузы:
TTL=60 s от создания набора, чтение его не продлевает.

4. Поиск строк и контекст:

```text
Повтори предыдущий опыт через search_text: path=R, pattern="**/*.txt",
searchPattern="swb-011-token", isRegex=false, maxDepth=100,
limit=3, pageSize=1, context=1. Пройди страницы командами Next page.
```

Всего 3 совпавшие строки, по одной на страницу. Два occurrences в строке
не расходуют limit дважды; context тоже не считается отдельным match.
Сохраняются limit warning, корректные пути и отсутствие дубликатов.

5. Контроль обычных snapshot/bundle — один небольшой прежний smoke по README:
   получить manifest/ZIP, проверить SHA-256 и открыть originals. Генерировать
   индекс целого диска для этой проверки не требуется.

## Что сохранить в отчёте

BUILD.json sourceCommit; результаты пунктов 1–4; фактические аргументы и ответы
при расхождении; прошёл ли snapshot/bundle smoke; завершился ли Ctrl+C штатно.
Не прикладывайте ключи, рабочие inventories или производственные документы.

При Invalid cursor после паузы выполните исходный запрос без cursor: это новый
scan. При TIMEOUT на большом дереве сначала сузьте path/pattern/depth; pageSize
уменьшает ответ, но не объём обхода. Для полного индекса большого дерева используйте
фоновый snapshot. Изменять count/TTL/cache budgets ради этого опыта не нужно.
